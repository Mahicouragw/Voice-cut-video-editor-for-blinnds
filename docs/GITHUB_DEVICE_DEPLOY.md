# One-command GitHub device authorization and deployment

## What the owner requested
Run `npm run all`, display a genuine GitHub device-code URL/code, and stop the pending authorization flow after **15 minutes** (or sooner if GitHub expires/rejects it). This is not a request to delete media, projects or branches after 15 minutes. Separate processing-request safeguards in the backend are unrelated to this authorization deadline.

## The command
From this prepared Git repository, with Node.js, GitHub CLI, FFmpeg and FFprobe available:

```bash
npm run all
```

The assistant can run this command in its workspace. The owner does not need to paste Git commands into Codespaces. Only the device approval must be completed in the owner's browser.

For a nonstandard GitHub CLI executable location, set `VOICECUT_GH_BIN` to its absolute path. In the agent workspace the official CLI is downloaded from github.com/cli/cli and verified against its published SHA-256 checksums.

## Authorization
1. The command starts the official GitHub CLI web/device flow in the background.
2. It prints the real GitHub verification URL and one-time user code. Neither is invented in advance.
3. Open the GitHub URL, enter that exact code, select your own account and review the permissions. Repository and workflow writes are needed to publish this update. GitHub CLI may request broader OAuth scopes than a single-repository app; review its authorization screen before approving.
4. Do not paste an API key, personal access token, password or recovery code into chat. The device user code generated by this flow is the only code intended to be displayed.
5. GitHub controls server-side device-code validity. This command additionally stops waiting after 900 seconds. Denied/expired codes do not lead to a push. A retry requires a new run and a new code; no silent retries of sign-in.

The 15-minute timer covers the **pending sign-in**, not subsequent builds and deployment, which may take longer. Successful authorization is not automatically revoked after 15 minutes.

## What happens after approval
- Verify the approving account can write to exactly `Mahicouragw/Voice-cut-video-editor-for-blinnds`.
- Install dependencies; run the unit, backend and browser tests; build public assets.
- Refuse to overwrite a changed main-branch baseline.
- Create a new branch, commit the prepared source, and push without force.
- Open a pull request. Wait for both website and Android PR workflows to pass. Failed/pending checks are not success.
- Configure Pages for GitHub Actions, merge the tested PR without bypassing branch protections, and wait for a successful main-branch Pages deployment.
- Print the actual deployment URL and workflow result. No remote branch is deleted.

If account permissions, branch protections, environment approvals or tests block progress, the command stops and reports the real issue. It does not claim deployment succeeded or disable safety controls to force it.

## Credentials and external services
Temporary GitHub credential files are held in a private cache directory, not source files, then removed when the command completes or the pending sign-in expires. A recoverable failure after authorization pauses for up to 30 minutes so the agent can repair it without another sign-in; cleanup follows that pause, or an earlier stop. This troubleshooting lifetime is separate from the 15-minute pending device-code limit. Abrupt process termination can interrupt cleanup; the cache is excluded from shared workspace snapshots. Removing a local file is not revoking the GitHub CLI OAuth grant. Review/revoke that grant in GitHub account settings when appropriate.

GitHub approval does not authorize Render billing, provision a paid AI backend, or create OpenAI/ElevenLabs API keys. Those require separate owner-controlled service authorization and private environment configuration. The website can be published first; cloud AI remains unavailable until the backend is configured.
